# TokenPulse UI 设计

本设计依据[完整设计方案](token-pulse-design.md)第 2、7、12、13、14、16、18 节，定义桌面统计窗口与悬浮小窗的视觉、布局和交互。设计范围是 Windows 优先的本地桌面工具，两个窗口共享同一后台统计结果。

交付日期：2026 年 10 月 1 日。

## 1. 交付内容与查看方式

- [可点击 HTML 原型](../../prototypes/token-pulse-ui.html)：直接用 Edge 或 Chrome 打开，不需要安装依赖或启动服务器。
- [默认深色总览](../images/token-pulse-overview.png)。
- [可选浅色总览](../images/token-pulse-light.png)。
- [会话详情](../images/token-pulse-session.png)。
- [紧凑悬浮窗](../images/token-pulse-floating-compact.png)与[展开悬浮窗](../images/token-pulse-floating-expanded.png)。

原型顶部的“预览状态”和主题按钮属于设计评审工具栏，不进入正式应用。所有用量、会话、费用、目录状态及时间均为合成演示数据；价格系数为虚构值。原型不读取真实日志，不修改系统设置，不执行真实导入、重建、备份或删除。导出功能会生成当前筛选的演示 CSV / JSON。

## 2. 视觉方向

采用用户提供的 CC GUI 用量统计截图作为视觉依据：深灰工作区、近黑内容面板、窄图标导航、中央超大总量、绿色费用、大圆角容器和密集明细表。主窗口默认深色，保留可选浅色与跟随系统主题；小窗采用相同配色和边界。

总量是画面的视觉中心，94 px 的粗体数字居中显示。费用使用绿色，放在总量下方，紧邻“已计价部分估算”和覆盖率。蓝色分解条与下方堆叠趋势图使用一致的语义颜色，用户能够持续识别非缓存输入、缓存输入和输出。缓存占比的分母始终是输入总数。

日期页签和组合筛选放在主统计面板顶部；总量、费用、分解条与两张摘要卡构成一个完整大面板。下一个大面板提供“每日明细 / 项目用量”页签与密集表格；趋势、最近会话和热力图放在后续区域。布局沿用参考图的阅读顺序，并增加当前方案需要的覆盖说明。

界面默认中文，保留 Codex 日志中的模型名和项目别名。文案使用“核对来源”“导出”“重建指定来源”等具体动作。

## 3. 设计变量

### 色彩

|角色|浅色|深色|用途|
|---|---|---|---|
|工作区背景|`#E9E9EB`|`#202020`|工作区与评审背景|
|内容表面|`#FFFFFF`|`#171717`|统计面板、小窗与数值区域|
|次级表面|`#F3F3F4`|`#242424`|导航、选中页签、上下文区域|
|主要文字|`#242426`|`#F2F2F3`|标题与关键数值|
|次级文字|`#727277`|`#929294`|说明、单位与时间|
|交互 / 非缓存输入|`#347CF5`|`#3880F6`|主要操作、非缓存输入|
|缓存输入|`#85ACDF`|`#78A7FA`|缓存部分，始终配文字标签|
|输出总数|`#637489`|`#A4A6AD`|输出部分，推理为其中子项|
|边线|`#E0E0E3`|`#303032`|分隔与容器边界|
|费用 / 采集正常|`#009F78`|`#00A67E`|估算费用、状态点及文字|
|需要检查|`#986012`|`#D9B16D`|覆盖缺口、来源不可读、待确认记录|

深色导航选中块使用 `#087DC7`；摘要卡边框为 `#414144`。参考图的颜色主要用于组织层级，独立应用保留自己的品牌与页面名称，不复刻 IDE 的通知栏和无关功能入口。

红色仅在正式实现中用于明确的失败或破坏性操作。状态必须有文字和必要的解释，不能仅靠颜色表达。热力图为另外一套连续强度刻度，未导入和未来日期使用虚线空格，与真实零值区分。

### 字体与数字

- Windows 正文优先 `Segoe UI Variable Text`、`Microsoft YaHei UI`；其他平台使用相应系统中文字体，不依赖网络字体。
- 数字优先 `Bahnschrift` / `Segoe UI`，使用等宽数字特性，避免数值更新时横向跳动。
- 页面标题 28 px；区块标题 15 px；正文 13 px；总览表格 14 px，其他表格 12 px；辅助文字 11–12 px。
- 总览主数字 94 px、居中粗体，小窗主数字 33 px，会话详情主数字 38 px。总览费用 28 px、绿色。
- 使用 `K`、`M` 缩写控制宽度；悬停或点击数字查看原始完整整数。Token 总量不通过浮点数累加，正式实现从十进制字符串格式化。
- 主数字与费用居中；页签、摘要卡和正文左对齐；数值列右对齐。不同数量级使用相同单位表达规则。

### 几何与密度

- 原生统计窗口建议默认 1280 × 860 DIP，最小 960 × 680 DIP；内容超过可用高度时滚动。
- 主导航约 72 DIP，使用图标与悬停名称；内容边距 32 DIP；区域间距 22 DIP；总览表格行高约 51 DIP。
- 普通按钮圆角 7 DIP，大统计面板 21 DIP，摘要卡 15 DIP，小窗 14 DIP。主窗口的边框由系统窗口壳管理。
- 常用按钮约 34–38 DIP 高；小窗操作为紧凑鼠标目标，正式实现增加可点击的透明边距。
- 不使用持续闪烁、跑马数字、装饰渐变或自动弹出窗口。主题变化与数字更新无需额外动画。

## 4. 信息架构

```text
统计主窗口
├─ 总览          可信总量 → 输入输出分解 → 趋势 → 最近会话 / 覆盖
├─ 模型统计      模型消耗、占比、缓存占比、估算与价格匹配
├─ 项目统计      项目消耗、路径 / 别名、进入会话
├─ 会话统计      范围内累计消耗、回合、父子关系、最近请求上下文
├─ 用量明细      时间、归属、Token 向量、计算依据
├─ 采集诊断      来源、导入、格式 / 计数问题、重建
└─ 设置          数据来源 / 显示与窗口 / 价格规则 / 数据与备份

悬浮小窗
├─ 紧凑          今日可信总量、输入缓存占比、时间和状态
└─ 展开          输入输出分解、全部来源 / 固定会话选择
```

模型、项目和会话不再合并为一个复杂报表入口，让三种不同的统计任务可以直接进入。采集诊断与设置放在导航下半区；导航底部固定采集状态和“显示悬浮窗”。

## 5. 总览布局

```text
┌───────────┬───────────────────────────────────────────────────┐
│           │ 用量总览                         核对来源   导出   │
│ 图标导航  │ ┌───────────────────────────────────────────────┐ │
│           │ │ 日期页签 / 来源、模型、项目筛选               │ │
│           │ │                可信 Token 总量                │ │
│           │ │                   3.21M                       │ │
│           │ │                绿色估算 + 覆盖率              │ │
│           │ │ 分解条                                        │ │
│           │ │ Codex 摘要卡 / 输入缓存卡       未计价与诊断   │ │
│           │ └───────────────────────────────────────────────┘ │
│           │ 每日明细 / 项目用量                             │
│           │ 日期、总量、非缓存、输出、缓存、推理、会话数     │
│ 采集状态  │ 用量趋势                         最近会话       │
│ 显示小窗  │ 近期活动热力图                                  │
│           ├─────────────────────────────────────────────────┤
│           │ 统计时区                           最近快照时间  │
└───────────┴───────────────────────────────────────────────────┘
```

顶部筛选沿用到模型、项目、会话和明细。正式应用日期默认今天；设计原型默认近 7 天，以便检查完整的每日明细排版。可选今天、近 7 天、近 30 天和自定义日期；开始和结束日期在界面均含当天，后台转换为指定时区的左闭右开区间。

来源、模型、项目可组合筛选；会话级筛选由会话详情和小窗固定入口进入。正式实现补充可搜索的会话筛选器，展示所有启用条件。重置清除维度条件并回到今天。

趋势沿用顶部筛选。热力图显式标注独立的近 26 周范围，继承来源、模型和项目条件；选择某天后正式实现更新统一日期筛选。无原始历史时以“历史未导入”标记，不能用零填补覆盖缺口。

总览包含“可信总量”和“待确认观察”的独立表达。若存在计数歧义，页面顶部展示具体原因并进入诊断；待确认量不能以可信总量的一部分绘制，也不能在未知时显示为 0。

|用量明细|记录时间、项目、模型、分解、总量、计算依据|分页、定位会话；正式实现支持按时间或消耗排序、检查原始向量和质量标记|

辅助页面沿用统一的筛选、数值格式、未知值和费用表达。统计为空时保留筛选区，使用户能够调整条件。

## 7. 会话详情

采用右侧 445 DIP 抽屉，保持用户与列表的关联。顶部显示会话与项目；随后分开显示两个区域：

1. **所选范围累计消耗**：来自用量事件汇总，展示同样的三段分解。
2. **最近请求上下文**：显示最近可信快照、容量和快照时间；存在可信窗口容量时才展示占比。

上下文快照不随日期筛选伪装成历史累计指标，应始终标明时间。缺少容量显示“窗口容量未知”；缺少快照显示“未知”，不绘制百分比。

下方展示模型、来源、事件时刻归属的项目、父会话和可靠用户回合数。原型以最近用量事件演示列表；正式实现增加按可靠 `turn_id` 聚合的回合列表，不把一条请求当作完整回合。不加载聊天正文。

“定位来源日志”仅在当前来源仍可读时可用；不可读时显示原因。按 Escape 关闭详情，焦点回到打开详情的入口。

## 8. 悬浮小窗

### 紧凑模式：280 × 160 DIP

```text
┌────────────────────────────────┐
│ ● TokenPulse       置顶  +  ×   │ ← 专用拖动区
│ 683.1K                         │ ← 点击数字展开分解
│ 全部来源 · 今日可信 Token      │
│ 输入缓存 68.1% · 14:32  打开统计│
└────────────────────────────────┘
```

缓存占比标明“输入缓存”，分母是包含缓存的输入总数。时间是最近成功快照或最后来源记录时间，正式实现通过悬停说明区分。没有新消耗不代表采集失败。

### 展开模式：360 × 320 DIP

在紧凑内容下增加分解条、三项数值和会话选择器。默认“全部来源 · 今日用量”；固定会话后显示其项目 / 名称与消耗起点。原型固定会话展示今日 00:00 后该会话消耗，正式实现支持明确的自选消耗起点。

会话选择不会随新活跃会话自动改变。点击“打开统计”带入同一会话和日期条件。悬浮窗隐藏只影响窗口，正式应用后台继续采集。

标题区拖动；按钮不触发拖动。原型将位置限制在浏览器可视区，正式桌面壳负责多屏工作区、缩放与重启恢复。

置顶、透明度、系统级穿透和恢复快捷键由桌面壳实现。穿透启用前，必须注册并验证恢复快捷键；冲突时不启用穿透。托盘保留恢复交互入口。

## 9. 数据状态与文案

|状态|呈现|用户可执行动作|
|---|---|---|
|加载 / 首次导入|显示已处理文件数；总数仍在发现时不展示伪精确百分比|查看诊断、暂停或安全取消，之后恢复|
|完整可用|正常汇总，保留覆盖与最近快照信息|筛选、导出、核对来源|
|覆盖不全|顶部浅琥珀提示具体原因；各模块标明缺口|查看待确认记录、补导入或配置价格|
|旧数据|保留最近成功数值；显示不可读来源和成功时间|重新检测、修正目录或等待来源恢复|
|查询失败|说明失败，不把失败值替换成零；后台可用时诊断入口保留|重试、查看诊断|
|未发现来源|“选择 Codex 数据目录”|选择目录、检测可读性|
|真实零用量|“今天还没有用量记录”，明确已成功核对|调整日期、保持后台运行|
|筛选无匹配|“没有匹配的用量记录”|调整条件或重置|
|历史尚未导入|“所选时间段历史尚未导入”，不展示零趋势|导入历史|

采集器健康与统计完整程度分别表达。“后台采集正常”不代表所有模型均可计价。正式实现由快照的 coverage / quality 状态确定提示，不让用户通过颜色猜测。

原型提供正常、覆盖不全、暂不可读、首次导入、未发现来源、今日无用量和查询失败七种预设，筛选无匹配通过组合条件呈现。暂不可读和覆盖不全状态保留演示数值。首次导入仅演示提示和来源进度，不模拟真实文件任务。

## 10. 统计与费用表达规则

```text
非缓存输入 = 输入总数 - 缓存输入
可验证总量 = 输入总数 + 输出总数
三段展示   = 非缓存输入 + 缓存输入 + 输出总数
```

推理为输出子项，仅作为辅助行显示。缓存输入不重复加到总量，推理不重复计费。原型今日数据用于检查：

|数值|Token|
|---|---:|
|输入总数|630,630|
|其中缓存输入|429,566|
|非缓存输入|201,064|
|输出总数|52,437|
|其中推理输出|19,926|
|可信总量|683,067|
|未计价 Token|44,355|

费用标题采用“已计价部分估算”，紧邻覆盖率和依据入口。未计价 Token 继续参与可信总量，价格未知时费用字段显示“未计价”。不能推断订阅实付、扣款或剩余额度。

价格详情展示模型匹配、规则来源、生效时间、币种、三项单价、估算方式、覆盖率及重算时间。正式实现提供按事件时点价格与按指定当前价格两种明确方式。

导出采用当前筛选与同一快照。隐私模式默认勾选隐藏项目名称与路径。JSON 包含时区、过滤条件、统计口径、价格规则、未计价标记和解析器版本；正式 CSV 补充快照、时区、质量标记或伴随元数据文件，并防止公式注入。

## 11. 系统行为与可访问性

- 关闭主窗口或小窗只隐藏窗口。托盘包含打开统计、显示小窗、隐私模式、核对来源、恢复交互和明确退出。
- 数据变更不抢焦点，不弹出窗口。刷新保持旧数据与原筛选，避免界面闪成零。
- 主窗口与悬浮窗使用相同主题和隐私设置。路径与会话名称使用替代文本，费用隐藏；隐私模式同时覆盖详情和小窗。正式实现还须隐藏工具提示、可访问名称和筛选器中的敏感标签。
- 键盘焦点可见；对话框与详情支持 Escape、焦点约束及返回触发入口；数值列使用等宽数字。
- 桌面主窗口优先保证 960 DIP 以上的操作密度。原型额外适配 390 px 评审视口，使设计可在窄窗口中查看；不代表新增移动端产品。
- 深色模式保持同一信息层级。缩放、高对比度、系统字体放大和多屏操作需要在正式 Tauri 应用中验证。

## 12. 原型覆盖与实现接入

### 已实现的演示交互

导航、日期 / 来源 / 模型 / 项目筛选、自定义日期、每日 / 项目汇总表页签、缓存口径详情、小时 / 日 / 月趋势、会话排序与详情、明细分页、设置页签、主题、隐私模式、小窗展开 / 固定 / 拖动、状态切换及 CSV / JSON 导出。

### 仍需接入的正式能力

实际的 Rust 采集、SQLite 与 Tauri IPC；来源选择和检测；任务进度、取消与恢复；价格规则编辑及实际价格快照；原生托盘、置顶、穿透与快捷键；多屏位置恢复；完整会话筛选、回合列表和分页；备份、恢复、更新及数据删除。

正式前端按 `AppShell`、`FilterBar`、`TokenBreakdown`、`UsageTrend`、`SessionDrawer`、`CoverageNotice`、`SourcePanel`、`FloatingWindow` 等职责拆分。查询状态与评审状态分离，演示工具栏不进入发布版本。

`get_snapshot` 提供总量、分解和覆盖；`query_series` 提供趋势；`query_sessions` 和 `get_context_snapshot` 支撑会话；`query_usage_events` 支撑明细；`manage_sources`、`start_job`、`get_job` 和设置接口支撑管理操作。全部查询以同一 `revision` 为基准，并用 `usage_changed` 重新取快照。

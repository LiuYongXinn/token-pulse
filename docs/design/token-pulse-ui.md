# TokenPulse UI 设计

M09g1b 已在正式价格设置页接内置官方目录：沿用原规则 / 别名区域，追加核实日期、参考说明、模型搜索、处理模式选择及只读档位单价。全球 API 参考与账户额度 / 订阅实付分别表达；有条件的价格明确说明需要的请求上下文 / 缓存写入证据，条件不足保持未计价。历史目录固定价格修订，读取失败可独立重试，隐私隐藏后关闭重新查询而不恢复旧搜索。深 1280 / 浅 960 窄屏六列布局已检查；实际 Win10 WebView 搜索 / 模式 / 历史 / 隐私通过，完整条件计价、持久缓存与独立重估继续实施。

正式 UI 按[已确认范围](../development/implementation-plan.md#7-已确认的剩余功能范围2026-10-02)交付：诊断仅保留来源状态、扫描时间、错误原因、必要定位与基本重建进度；取消开机启动、额外快捷键、原文采样、完整任务历史和继承证据浏览器。保留 notify、自动更新、模型别名 / 离线价格、费用重估、账户额度与任务栏，验证 Windows 10 / 11、多屏与各档 DPI；原型中 WSL 与已取消功能仅为历史演示。

本设计依据[完整设计方案](token-pulse-design.md)第 2、7、12、13、14、16、18 节，定义桌面统计窗口、悬浮小窗与任务栏模式的视觉、布局和交互。设计范围是 Windows 优先的本地桌面工具，三种显示入口共享同一后台统计结果。

交付日期：2026 年 10 月 1 日。

正式实施入口：[详细开发设计](development-design.md)，包含本 UI 对应的真实数据、模块、接口及验收要求。

## 2. 视觉方向

用户提供的 CC GUI 截图仅作为视觉风格依据：深灰底色、近黑内容表面、蓝色强调、绿色费用、柔和圆角与细边线。页面的导航宽度、信息布局、阅读顺序和功能分区由 TokenPulse 自身方案确定。

保留完整文字导航与统一顶部筛选。总览采用左右分区：左侧依次展示可信总量、输入输出分解、用量趋势与近期活动；右侧保留最近会话和统计覆盖。费用在汇总区域右侧，紧邻覆盖率与依据入口。主数字左对齐，保持 48 px，确保趋势和覆盖信息同时可见。

三段 Token 分解条与堆叠趋势图沿用同一套颜色。用户在总览、会话详情和小窗之间切换时，能够持续识别非缓存输入、缓存输入和输出。缓存占比的分母始终是输入总数。

深色内容区通过明度、边线与留白区分层次。主窗口默认深色，保留可选浅色与跟随系统主题。文案使用“核对来源”“重建指定来源”等具体动作；界面默认中文，模型名和项目别名保留原值。

## 3. 设计变量

### 色彩

|角色|浅色|深色|用途|
|---|---|---|---|
|工作区背景|`#E9E9EB`|`#202020`|工作区与评审背景|
|内容表面|`#FFFFFF`|`#171717`|统计面板、小窗与数值区域|
|次级表面|`#F3F3F4`|`#242424`|导航、选中页签、上下文区域|
|主要文字|`#242426`|`#F2F2F3`|标题与关键数值|
|次级文字|`#727277`|`#A0A0A4`|说明、单位与时间|
|交互 / 非缓存输入|`#347CF5`|`#3880F6`|主要操作、非缓存输入|
|缓存输入|`#85ACDF`|`#78A7FA`|缓存部分，始终配文字标签|
|输出总数|`#637489`|`#A4A6AD`|输出部分，推理为其中子项|
|边线|`#E0E0E3`|`#303032`|分隔与容器边界|
|费用 / 采集正常|`#009F78`|`#00A67E`|估算费用、状态点及文字|
|需要检查|`#986012`|`#D9B16D`|覆盖缺口、来源不可读、待确认记录|

深色导航选中块使用 `#087DC7`，选中项保留文字名称。参考图的颜色与表面质感用于组织层级，独立应用保留自身信息架构。

红色仅在正式实现中用于明确的失败或破坏性操作。状态必须有文字和必要的解释，不能仅靠颜色表达。热力图为另外一套连续强度刻度，未导入和未来日期使用虚线空格，与真实零值区分。

### 字体与数字

- Windows 正文优先 `Segoe UI Variable Text`、`Microsoft YaHei UI`；其他平台使用相应系统中文字体，不依赖网络字体。
- 数字优先 `Bahnschrift` / `Segoe UI`，使用等宽数字特性，避免数值更新时横向跳动。
- 页面标题 25 px；区块标题 15 px；正文 13 px；表格 12 px；辅助文字 11–12 px。
- 总览主数字 48 px、左对齐，小窗主数字 33 px，会话详情主数字 38 px。总览费用 25 px、绿色。
- 使用 `K`、`M` 缩写控制宽度；悬停或点击数字查看原始完整整数。Token 总量不通过浮点数累加，正式实现从十进制字符串格式化。
- 主内容与主数字左对齐；汇总区域费用和表格数值列右对齐。不同数量级使用相同单位表达规则。

### 几何与密度

- 原生统计窗口建议默认 1280 × 860 DIP，最小 960 × 680 DIP；内容超过可用高度时滚动。
- 主导航约 205 DIP，使用图标加文字；内容边距 32 DIP；区域间距 24 DIP；表格行高约 56 DIP。
- 普通按钮圆角 7 DIP，独立信息面板 14 DIP，小窗 14 DIP。主窗口的边框由系统窗口壳管理。
- 常用按钮约 34–38 DIP 高；小窗操作为紧凑鼠标目标，正式实现增加可点击的透明边距。
- 不使用持续闪烁、跑马数字、装饰渐变或自动弹出窗口。主题变化与数字更新无需额外动画。

## 4. 信息架构

```text
统计主窗口
├─ 总览          可信总量 → 输入输出分解 → 趋势 → 最近会话 / 覆盖
├─ 模型统计      模型消耗、占比、缓存占比、估算与价格匹配
├─ 项目统计      项目消耗、路径 / 别名、进入会话
├─ 会话统计      范围内累计消耗、回合、父子关系、最近请求上下文
├─ 用量明细      时间、归属、Token 向量、计算依据
├─ 采集诊断      来源、导入、格式 / 计数问题、重建
└─ 设置          数据来源 / 显示与窗口 / 任务栏显示 / 价格规则

悬浮小窗
├─ 紧凑          今日可信总量、已计价估算、账户剩余额度、周重置与采集状态
└─ 展开          保留估算费用，增加输入输出分解、全部来源 / 固定会话选择
```

模型、项目和会话不再合并为一个复杂报表入口，让三种不同的统计任务可以直接进入。采集诊断与设置放在导航下半区；导航底部固定采集状态和“显示悬浮窗”。

## 5. 总览布局

```text
┌───────────┬───────────────────────────────────────────────────┐
│           │ 用量总览                         核对来源          │
│ 文字导航  │ 日期范围   来源   模型   项目   重置               │
│           ├───────────────────────────────────────────────────┤
│           │ 可信 Token 总量        已计价估算  │ 最近会话      │
│           │ 会话数 / 用量事件数    价格覆盖率  │ 项目、消耗    │
│           │ 三段分解条 + 绝对值               │ 详情入口      │
│           ├─────────────────────────────────┼───────────────┤
│           │ 用量趋势                          │ 统计覆盖      │
│           │ 堆叠柱图 · 小时 / 日 / 月         │ 来源、未计价  │
│           ├─────────────────────────────────┤               │
│ 采集状态  │ 近期活动热力图                    │               │
│ 显示小窗  ├─────────────────────────────────┴───────────────┤
│           │ 统计时区                           最近快照时间  │
└───────────┴───────────────────────────────────────────────────┘
```

顶部统一筛选独立于内容面板，沿用到模型、项目、会话和明细。日期默认今天，可选近 7 天、近 30 天和自定义日期；开始和结束日期在界面均含当天，后台转换为指定时区的左闭右开区间。

来源、模型、项目可组合筛选；会话级筛选由会话详情和小窗固定入口进入。正式实现补充可搜索的会话筛选器，展示所有启用条件。重置清除维度条件并回到今天。

趋势沿用顶部筛选。热力图显式标注独立的近 26 周范围，继承来源、模型和项目条件；选择某天后正式实现更新统一日期筛选。无原始历史时以“历史未导入”标记，不能用零填补覆盖缺口。

总览包含“可信总量”和“待确认观察”的独立表达。若存在计数歧义，页面顶部展示具体原因并进入诊断；待确认量不能以可信总量的一部分绘制，也不能在未知时显示为 0。

## 7. 会话详情

采用右侧 445 DIP 抽屉，保持用户与列表的关联。顶部显示会话与项目；随后分开显示两个区域：

1. **所选范围累计消耗**：来自用量事件汇总，展示同样的三段分解。
2. **最近请求上下文**：显示最近可信快照、容量和快照时间；存在可信窗口容量时才展示占比。

上下文快照不随日期筛选伪装成历史累计指标，应始终标明时间。缺少容量显示“窗口容量未知”；缺少快照显示“未知”，不绘制百分比。

下方展示模型、来源、事件时刻归属的项目、父会话和可靠用户回合数。原型以最近用量事件演示列表；正式实现增加按可靠 `turn_id` 聚合的回合列表，不把一条请求当作完整回合。不加载聊天正文。

“定位来源日志”仅在当前来源仍可读时可用；不可读时显示原因。按 Escape 关闭详情，焦点回到打开详情的入口。

## 8. 悬浮小窗

### 紧凑模式：280 × 220 DIP

```text
┌────────────────────────────────┐
│ ● TokenPulse       置顶  +  ×   │ ← 专用拖动区
│ 683.1K                  $0.57  │ ← 数字展开分解，费用查看依据
│                   已计价估算  │
│ 全部来源 · 今日可信 Token      │
│ 输入缓存 68.1% · 14:32  打开统计│
│ 5小时剩余 72%     周剩余 38%    │
│ 周重置 10/04 10:25    剩 2天19时│
└────────────────────────────────┘
```

缓存占比标明“输入缓存”，分母是包含缓存的输入总数。时间是最近成功快照或最后来源记录时间，正式实现通过悬停说明区分。没有新消耗不代表采集失败。

用量数字右侧增加绿色费用，标注“已计价估算”。紧凑与展开模式均显示，保持 280 × 220 和 360 × 380 DIP。金额与小窗的全部来源或固定会话采用同一范围，不受主窗口独立筛选影响。切换固定会话时费用同步变化。

点击金额查看当前范围、已计价估算、价格覆盖率和未计价 Token，并可进入价格规则。全部用量都没有价格时显示“未计价”；未配置来源显示“—”；已确认零用量显示 `$0.00`。部分未计价时只汇总已计价部分，通过提示与详情说明覆盖。隐私模式同时隐藏金额和费用说明。

账户额度区显示短周期和周剩余百分比、周重置时间及倒计时，点击查看各周期详情。两种模式均可直接查看。仅周窗口、未连接及更新失败采用各自状态，详见[账户额度显示设计](account-quota.md)。账户数据独立于会话用量，不随固定会话变化。

### 展开模式：360 × 380 DIP

在紧凑内容下增加分解条、三项数值和会话选择器。默认“全部来源 · 今日用量”；固定会话后显示其项目 / 名称与消耗起点。原型固定会话展示今日 00:00 后该会话消耗，正式实现支持明确的自选消耗起点。

会话选择不会随新活跃会话自动改变。点击“打开统计”带入同一会话和日期条件。悬浮窗隐藏只影响窗口，正式应用后台继续采集。

标题区拖动；按钮不触发拖动。原型将位置限制在浏览器可视区，正式桌面壳负责多屏工作区、缩放与重启恢复。

置顶、透明度、系统级穿透和恢复快捷键由桌面壳实现。穿透启用前，必须注册并验证恢复快捷键；冲突时不启用穿透。托盘保留恢复交互入口。

### 任务栏模式

新增类似 TrafficMonitor 的任务栏读数，默认在系统托盘左侧，两行显示 Token、绿色估算费用、短周期与周剩余百分比、周重置时间。文字融入任务栏，不沿用主窗口卡片布局。任务栏与小窗可独立开启，并共享全部来源 / 固定会话范围和隐私设置。

悬停查看完整分解、计价覆盖与额度倒计时；单击打开现有展开小窗，双击打开同范围统计，右键提供设置、隐私与隐藏入口。设置新增“任务栏显示”页签，支持布局、位置、显示项目与失败回退。原型底部加入示意任务栏，提供拥挤、自动隐藏、Explorer 恢复和嵌入失败场景。

原生嵌入、DPI、多显示器、宿主恢复与空间预留决策见[Windows 任务栏显示模式](taskbar-display.md)。Windows 10 优先适配，Windows 11 单独验证；当前浏览器预览不会更改系统任务栏。

## 9. 数据状态与文案

|状态|呈现|用户可执行动作|
|---|---|---|
|加载 / 首次导入|显示已处理文件数；总数仍在发现时不展示伪精确百分比|查看诊断、暂停或安全取消，之后恢复|
|完整可用|正常汇总，保留覆盖与最近快照信息|筛选、核对来源|
|覆盖不全|顶部浅琥珀提示具体原因；各模块标明缺口|查看待确认记录、补导入或配置价格|
|旧数据|保留最近成功数值；显示不可读来源和成功时间|重新检测、修正目录或等待来源恢复|
|查询失败|说明失败，不把失败值替换成零；后台可用时诊断入口保留|重试、查看诊断|
|未发现来源|“选择 Codex 数据目录”|选择目录、检测可读性|
|真实零用量|“今天还没有用量记录”，明确已成功核对|调整日期、保持后台运行|
|筛选无匹配|“没有匹配的用量记录”|调整条件或重置|
|历史尚未导入|“所选时间段历史尚未导入”，不展示零趋势|导入历史|

采集器健康与统计完整程度分别表达。“后台采集正常”不代表所有模型均可计价。正式实现由快照的 coverage / quality 状态确定提示，不让用户通过颜色猜测。

原型提供正常、覆盖不全、暂不可读、首次导入、未发现来源、今日无用量和查询失败七种预设，筛选无匹配通过组合条件呈现。暂不可读和覆盖不全状态保留演示数值。首次导入仅演示提示和来源进度，不模拟真实文件任务。

## 10. 统计与费用表达规则

```text
非缓存输入 = 输入总数 - 缓存输入
可验证总量 = 输入总数 + 输出总数
三段展示   = 非缓存输入 + 缓存输入 + 输出总数
```

推理为输出子项，仅作为辅助行显示。缓存输入不重复加到总量，推理不重复计费。原型今日数据用于检查：

|数值|Token|
|---|---:|
|输入总数|630,630|
|其中缓存输入|429,566|
|非缓存输入|201,064|
|输出总数|52,437|
|其中推理输出|19,926|
|可信总量|683,067|
|未计价 Token|44,355|

费用标题采用“已计价部分估算”，紧邻覆盖率和依据入口。未计价 Token 继续参与可信总量，价格未知时费用字段显示“未计价”。不能推断订阅实付、扣款或剩余额度。

价格详情展示模型匹配、规则来源、生效时间、币种、三项单价、估算方式、覆盖率及重算时间。正式实现提供按事件时点价格与按指定当前价格两种明确方式。

正式应用取消顶部导出按钮及“数据与备份”设置页签，不提供导出、手动备份、备份恢复或数据清除入口。迁移保护与专门故障恢复界面也不再追加；原型中的相关旧入口不纳入正式 UI 验收。

## 11. 系统行为与可访问性

- 关闭主窗口或小窗只隐藏窗口。托盘包含打开统计、显示小窗、隐私模式、核对来源、恢复交互和明确退出。
- 数据变更不抢焦点，不弹出窗口。刷新保持旧数据与原筛选，避免界面闪成零。
- 主窗口与悬浮窗使用相同主题；任务栏融入系统任务栏背景，三种入口共享隐私设置。路径与会话名称使用替代文本，费用隐藏；隐私模式同时覆盖详情和小窗。正式实现还须隐藏工具提示、可访问名称和筛选器中的敏感标签。
- 键盘焦点可见；对话框与详情支持 Escape、焦点约束及返回触发入口；数值列使用等宽数字。
- 桌面主窗口优先保证 960 DIP 以上的操作密度。原型额外适配 390 px 评审视口，使设计可在窄窗口中查看；不代表新增移动端产品。
- 深色模式保持同一信息层级。缩放、高对比度、系统字体放大和多屏操作需要在正式 Tauri 应用中验证。

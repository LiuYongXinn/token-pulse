# 日期切换与统计聚合复用

## CC GUI 的参考实现

2026-10-07 检查本机 `E:/Documents/Code/jetbrains-cc-gui` 的统计接入和 `C:/Users/Amin/.tokentracker/tracker/app/src/lib/local-api.js`。当前 JetBrains CC GUI 的 `UsageDashboardSection` 接入 TokenTracker，统计请求通过 `TokenTrackerHandler` 转发至本地服务。

本地服务的 `readQueueData` 按文件身份、大小和纳秒修改时间保留解析并去重后的队列；同文件追加时只解析新增尾部。`aggregateByDay` 用 WeakMap 保留该队列对应的每日聚合，键包含时区和价格修订。`usage-summary` / `usage-daily` 在这些每日行中按日期筛选；不是每次切换都重读 Codex 原始日志。前端 `use-usage-data` 另有按范围保存的展示缓存，`api.ts` 合并同时发生的相同请求。

因此，值得参考的是把解析、聚合和查询准备放到切换之前。此检查没有实测 CC GUI 的点击延迟，也不把其他版本的历史统计实现视为当前实现。

## TokenPulse 原来的等待路径

TokenPulse 已有完整查询缓存、UTC 小时 rollup、范围公共汇总及重启展示缓存。缓存命中可以直接显示；但未访问的日期范围没有完整 DTO，原来的概览需要计算范围汇总、费用、趋势、近 26 周热力图、最近会话和核算版本。模型、项目、会话、明细查询也按该新范围准备。

近 26 周热力图的日期边界独立于所选统计范围。仅从今天切换到近 7 天或近 30 天，热力图的聚合范围通常不变，却原先仍重复计算。现有导航预读只准备当前日期的各页，没有提前准备其他日期。

## 本次实现

### 后端日历聚合缓存

`query/series_cache.rs` 在同一 Database 实例内保存精确日历聚合，最多 20 个范围 / 8 MiB 序列化结果。缓存身份包括数据库 ID、data / price / usage-view 修订、完整筛选、时区、准确起止毫秒和粒度；ID 集合排序去重，同一身份的并发读取合并计算。失败不入缓存，超大结果正常返回但不保存。

概览趋势和热力图都可复用该缓存。缓存仅保留桶边界和 TokenTotals；覆盖状态仍由调用方的同一 SQLite 事务组装，避免把另一个统计范围的待核对数量或来源健康带入结果。旧事务继续读取旧版本；新事实、来源或其他 view 修订变更使用新缓存身份。

### 前端快捷日期准备

`DatePresetCache.tsx` 等当前概览成功且非过期后，延迟 300 ms，通过 Rust 日期解析器准备今天、近 7 天、近 30 天的边界，再后台读取另外两个完整概览。当前来源、模型、项目、会话、费用基准和粒度随请求保留。后台工作沿用现有并发与容量限制，不展示额外组件。

日期解析结果与主窗口共用有界缓存，重用期限来自 Rust 给出的当前本地日结束边界。跨日、时区改变、系统时钟回退重新解析；预读完成前的旧范围、隐私代次和迟到结果不会替换当前日期。用户点击尚未完成的预读范围时，对应共享任务可提升到前台调度。

缓存已经准备完成时，快捷日期首次切换即可显示对应完整概览，无需等该次点击再发概览查询。刷新和变更通知继续按已有规则失效、重新读取。

## 精度与范围

不通过相加每日会话数得到周/月会话数：跨日会话会重复计数。回合身份、镜像去重、未知分项、精确费用以及来源/模型/项目/会话筛选仍由原权威查询负责。没有把所有原始日志传给前端。

本次预读只覆盖三个快捷日期的概览。模型、项目、会话、明细仍按各自完整查询缓存工作。任意未访问的自定义日期、预读未完成或结果已被逐出时，仍需要读取；自定义日期可以复用相同版本的热力图聚合。应用安装后的真实数据库点击时长不由合成 UI 测试推断。

# 账户额度显示设计

实施入口：[详细开发设计](development-design.md)，实际 DTO、连接 epoch 与权限见 [IPC 契约](ipc-contracts.md)。

本设计补充[完整设计方案](token-pulse-design.md)与 [UI 设计](token-pulse-ui.md)。根据新增需求，在悬浮窗与任务栏中展示当前连接账户的剩余额度百分比、周期重置时间和倒计时。原方案的日志采集与费用估算继续使用本地用量账本；账户额度由独立的数据源提供。

## 显示内容

紧凑模式与展开模式均包含：

- 当前范围的可信 Token 总量及已计价费用估算。
- 短周期剩余额度百分比，例如“5 小时剩余”。周期名称根据数据源返回的实际长度生成。
- 周剩余额度百分比。
- 周额度重置日期、时间和剩余倒计时。
- 连接失败、旧快照和数据缺失等明确状态。

点击额度区查看账户范围、各周期剩余百分比、各周期重置时间、统计时区和快照时间。紧凑窗调整为 280 × 220 DIP，展开窗调整为 360 × 380 DIP。

固定会话只改变 Token 和费用范围，账户额度仍表示当前连接账户。悬浮窗的主数字、估算费用和账户额度分别表达各自口径。估算美元金额不能换算为账户剩余百分比。

任务栏常驻区采用紧凑百分比与周重置时间，悬停面板展示完整剩余条和倒计时；空间不足时精简常驻内容。与悬浮窗共享账户快照、桶选择、未知值与重置规则，详见[任务栏显示模式](taskbar-display.md)。

## 数据来源与边界

官方 Codex App Server 提供 `account/rateLimits/read` 查询和 `account/rateLimits/updated` 变更通知；优先处理 `rateLimitsByLimitId`，兼容单桶 `rateLimits`。窗口字段包括 `usedPercent`、`windowDurationMins` 和以秒为单位的 `resetsAt`。[官方接口说明](https://learn.chatgpt.com/docs/app-server)

接入通过用户明确配置的账户服务或受控 App Server 连接实现。账户信息读取属于可选能力，不要求本地日志采集器读取 `auth.json`、解析认证文件或推测账号。不能假定能直接连接 Codex 桌面应用内部服务。

2026-10-02 用户确认：直接复用本地已登录的 Codex 账户，不在 TokenPulse 新建登录、设备码或取消登录流程。通过用户选择的原生 Codex 服务及现有 Codex Home，由服务读取其已管理的登录状态；TokenPulse 先用 account/read（refreshToken=false）判断可用性，再读取额度。缺少或失效登录时保留 null 和“本地登录态不可用”，允许改选已登录 Home / 重新连接，不自动发起授权。原型合成快照不代替正式读取，运行也不依赖当前 Codex 对话工具。

额度桶按连接账户和 `limit_id` 隔离，默认选择明确的 Codex 桶。存在多个桶时，正式界面展示当前桶名称并提供选择，不将不同桶的剩余百分比求和或平均。

## 字段处理

|字段|展示规则|
|---|---|
|`usedPercent`|剩余 = `clamp(100 - usedPercent, 0, 100)`；缺失或无效显示“未提供”|
|`windowDurationMins`|决定周期名称；不能固定将 primary 认作 5 小时、secondary 认作周窗口|
|`resetsAt`|秒转换为毫秒后，按配置时区显示日期和时间；缺失显示“时间未提供”|
|快照获取时间|独立于本地日志的最近记录时间，用于说明账户数据的新鲜程度|
|账户 / 桶身份|限定快照归属；切换账户后重新查询，不能沿用前一个账户的数值|

周窗口根据实际返回的长度识别，常见 10080 分钟窗口标为“周”。只有周窗口时，保留周百分比并将短周期标为“未提供”。其他周期使用真实长度标签，正式实现允许展示额外窗口。

剩余条的填充方向为“可用比例”：剩余越多，条越长。低于或等于 20% 时使用琥珀色，同时保留百分比文字。真实 0% 显示 `0%`，与缺失数据区别明确。

## 重置与更新

- 显示绝对重置时间和相对倒计时；统一使用设置中的时区。
- 前端每分钟更新倒计时，不通过倒计时计算新的百分比。
- 到达重置时间后显示“等待额度更新”，请求新快照；不自行将百分比改为 100%。
- 数据服务收到变更通知后更新快照，前端收到相应修订通知后重查。
- 正式实现可在窗口重新打开、休眠恢复和用户刷新时重新读取；轮询应限流并对失败退避。
- 更新失败时保留旧快照，显示“旧快照 · 更新失败”，详情展示最近成功时间。
- 未连接时显示“账户额度 · 未连接”及连接入口，不能显示 0% 或假定满额。

## 接口与模块

新增 `AccountQuotaProvider`，独立于 Codex JSONL 适配器。它负责账户连接状态、额度查询与通知、桶选择和快照缓存，不修改 Token 账本。

建议前端接口：

|接口|职责|
|---|---|
|`get_account_quota`|返回当前选定账户及桶的周期窗口、状态、修订号、获取时间和错误类别|
|`refresh_account_quota`|触发受限速控制的账户额度读取，保留现有快照|
|`manage_account_connection`|连接已保存的本地 Codex 服务、断开及切换额度桶；复用现有登录态，不发起登录|
|`account_quota_changed`|通知额度快照变化，避免与本地 `usage_changed` 混用|

只缓存展示必要的额度字段、连接标识与获取时间。不将访问令牌、认证原文或账户工具返回的全部信息写入用量库、导出文件或设计原型。

## 正式实现进度（M12f / M12g）

设置页已提供元数据检测本地 Codex / Home、可核对草稿及独立保存 / 连接。总览右栏与小窗接入真实 DTO、实际周期 / 桶、剩余条、重置待更新、旧快照与共享隐私。没有本地来源时账户区仍独立显示，主筛选不修改额度。实现与自动 / 原生验证分别见 [检测验收](../development/local-account-detection.md) 和 [共享显示验收](../development/account-quota-verification.md)；实际账户长期刷新、通知、冷启动与任务栏仍需分别完成。

## 本次原型验证

以下仅记录先前原型验证，不属于正式应用的数据。

原型顶部增加“账户预览”，支持双周期、仅周窗口、额度偏低、未连接、更新失败和重置待更新六种状态。默认演示值为短周期剩余 72%、周剩余 38%；基准时间为 2026-10-01 14:32，周重置为 10 月 4 日 10:25。倒计时随打开原型后的时间推进。这些值均为合成数据。

检查内容包括：两种小窗尺寸与内容溢出、费用范围切换、账户额度不随会话变化、仅周窗口时的缺失表达、低额度提示、断开状态、过期快照、重置待更新、详情入口以及隐私模式。

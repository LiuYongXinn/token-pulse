# 会话标题显示

## 行为

会话列表、详情、父子会话、总览最近会话、明细、主窗口会话筛选和小窗会话选择统一优先显示 Codex 的会话标题。没有可用标题时依次回退到 Codex 会话 ID、TokenPulse 会话键。显示名称不会成为筛选键、分页键或核算身份；现有列表的悬停提示和详情仍保留会话键。

## 标题来源

从每个已启用来源根目录的 `session_index.jsonl` 只读采集 `id`、`thread_name` 和 RFC 3339 `updated_at`。只读标题索引，不读取对话正文来推断标题。

- 启动时读取，随后按采集服务的 `active_poll` 检查，默认 60 秒。恢复采集和请求重新扫描也会检查。
- 文件大小和修改时间未变化时跳过读取；没有可靠修改时间时重新读取。
- 同一会话取时间最新的有效条目；时间相同时以索引中靠后的有效条目为准。旧条目不能覆盖较新的已保存标题。
- 跳过格式错误、空白标题、无效时间和未完成的末尾行。单行上限 64 KiB，索引上限 64 MiB；超限或文件不可读时保留现有显示信息，不影响用量采集。
- 来源没有索引或索引未包含某个会话时，保留已有标题或显示 ID。索引不是完整会话清单，缺少条目不代表会话被删除。

## 存储和查询

Schema 19 新增 `session_titles`，以来源 ID 和 Codex 会话 ID 为联合主键，保存标题及更新时间。允许在日志完成导入之前采集标题。`session_labels` 视图集中实现标题与 ID 的回退；相同 Codex 会话 ID 的镜像共享最新标题，多来源同时间用来源 ID 保证稳定排序。

标题写入通过现有 Writer 事务完成，并核对来源仍启用且根目录未变。实际变更提升 `usage_view_revision`，由现有通知和缓存更新机制处理；重复读取不会提升修订。`data_revision`、`price_revision`、用量事件、账本及日志检查点保持原语义。已有 SQLite 分页快照继续使用查询时的标题，新查询使用新标题。

沿用现有迁移流程从 schema 18 升级到 19；不修改此前迁移文件。隐私模式继续通过现有 DTO 脱敏把标题替换为会话别名。

## 验证

- 解析测试：中文、CRLF、重复和过时记录、无效记录、未完成末尾行、超长记录。
- Store 测试：标题回退、改名、父会话、筛选搜索、小窗选择、隐私脱敏、分页标题冻结、视图修订与用量 / 费用修订分离、来源根目录校验。
- 后台测试：启动导入标题、没有日志追加时定期发现改名、索引消失后保留标题、源日志字节不变。
- 升级测试：schema 18 → 19 保留会话身份与统计修订，生成的升级前备份仍为 schema 18。

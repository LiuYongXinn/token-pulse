## 2. 当前公式与目标公式

已发布引擎的公式为：

```text
费用 = (输入总量 - 缓存命中量) × 输入单价
     + 缓存命中量 × 缓存单价
     + 输出总量 × 输出单价
```

推理 Token 包含在输出总量中，不能重复收费。以上公式只覆盖现有三费率规则，不是独立缓存写入的完整算法。未知值保持 null；缺少必要用量、规则不明确或算术溢出时保留 Token 并返回未计价原因。固定自定义单价只能给出用户指定依据的估算，不证明自动档位 / 模式识别已经实现。

独立缓存写入的目标公式为：

```text
普通输入 = 输入总量 - 缓存命中量 - 缓存写入量
费用 = 普通输入 × 普通输入单价
     + 缓存命中量 × 缓存命中单价
     + 缓存写入量 × 缓存写入单价
     + 输出总量 × 输出单价
```

缓存命中与写入是输入总量内分别计价的类别。必须检查两者之和不大于已知输入总量，非负整数与 checked 运算不能省略。不能先按普通输入收费再追加完整写入费用。缺失写入量与真实零不同；有独立写入价格但缺必要数量 / 条件时不猜测金额。仅在经确认的来源格式明确不报告独立写入、且适用规则确实不区分写入时，才按其原有语义估算。

金额继续使用每百万费率的 `10^9` 整数原子与 `10^-15` 币种费用原子，checked i128；聚合后统一舍入，币种分开，不改变 Token 账本。

缓存写入字段需要按来源层次解释：官方 Codex rollout / protocol 使用 `cache_write_input_tokens`，其 API 响应适配读取 `input_tokens_details.cache_write_tokens`。用户指出的 `last_token_usage` / `total_token_usage` 内 `cache_write_tokens` 也属于当前不支持格式；不能把 API 层字段名未经确认直接当成所有 rollout 版本的同义词。后续支持别名须明确格式证据、拒绝冲突双字段，不能忽略未知正数。原日志只读，不保存正文或认证；旧格式全历史自动重解析仍在取消范围内。

`gpt-6.1-sol` 已收录多个模式 / 上下文 / 写入价格，但不在 37 条自动参考规则中；当前完整计价未接通。不得通过把条件价格压成单条默认规则来宣称完成。

## 4. 扩展范围及更新方式

搜索调用、云端容器、文件存储等独立工具费用，以及图片、音频、实时语音和微调的专门用量 / 费用核算均未实现。这些需要独立的计量单位、身份、周期或媒体类型证据及专用规则，不能从文本 Token 推算，也不能把工具已包含的模型 Token 重复加计。它们单列为扩展计划，不自动扩大本次已经确认的本地文本工具交付范围。

生产应用使用随程序打包的离线目录；`scripts/update-offline-prices.mjs` 是开发者只读官方文档、审查差异后提交新目录的工具，不是运行时自动联网更新。运行时官方价格自动更新尚未实现，后续若纳入范围需验证来源、不可变历史版本和原子发布，失败保留旧目录；核实时间不能冒充历史价格生效日。

## 6. 缓存写入数量链路（M09h1a）

新增 nullable `UsageVector.cache_write_input`；适配器读取 rollout 的 `cache_write_input_tokens`，并明确定义用量对象内 `cache_write_tokens` 为本工具的兼容拼写，不冒充官方 rollout 字段。双字段值不同（含 null 与已知值冲突）拒绝，其他未知字段继续拒绝；字符串、布尔、小数和超 i64 范围不接受。缺失 / null 保持未知，真实 0 保持零。负数、命中 + 写入 > 输入及报告总量下界冲突由领域校验隔离。

累计差值包含写入计数；字段覆盖改变或无证明的下降不推进基线，明确阶段重置按新阶段核算。镜像 / 分叉的完整必要签名包含已知写入值；未知写入省略序列化，旧必要 JSON / 签名字节不变，不触发旧格式全历史自动重解析。写入不另加到输入 + 输出总量中。

schema v11 为 usage_events 增加 nullable 精确 INTEGER 字段与非负 / 包含关系约束；事件、必要观察、基线和检查点仍共用原事务，旧行保持 null。候选验证 / 切换及实际旧读取快照保留该分项。原始与核算 DTO 输出精确字符串，TokenTotals 独立返回值 / 覆盖 / 完整性；rollup cache version 升至 2，不读取旧五分项缓存。总览、会话详情和明细证据新增包含项；原 noncached_input 仍为输入 - 命中（包括写入），显示名改为“非缓存命中输入”，不能误称为四费率公式中的普通输入。

本阶段没有第四种价格费率，已知正数写入返回 insufficient_usage，保留 Token；已知零兼容原三费率结果。M09h2 接四费率及正确扣除算法，M09h3 / h4 接可靠请求长度 / 实际模式后才能完成条件模型计价。数量接入不代表官方所有条件可采集。正式安装 / 发布的 0.1.2 尚不包含本增量；此前被旧适配器拒绝的历史记录不会自动重读，受控手动补读与实际日志兼容继续收尾，不恢复已取消的全历史自动重解析范围。

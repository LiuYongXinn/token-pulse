## 2. 当前公式与目标公式

已发布引擎的公式为：

```text
费用 = (输入总量 - 缓存命中量) × 输入单价
     + 缓存命中量 × 缓存单价
     + 输出总量 × 输出单价
```

推理 Token 包含在输出总量中，不能重复收费。以上公式只覆盖现有三费率规则，不是独立缓存写入的完整算法。未知值保持 null；缺少必要用量、规则不明确或算术溢出时保留 Token 并返回未计价原因。固定自定义单价只能给出用户指定依据的估算，不证明自动档位 / 模式识别已经实现。

独立缓存写入的目标公式为：

```text
普通输入 = 输入总量 - 缓存命中量 - 缓存写入量
费用 = 普通输入 × 普通输入单价
     + 缓存命中量 × 缓存命中单价
     + 缓存写入量 × 缓存写入单价
     + 输出总量 × 输出单价
```

缓存命中与写入是输入总量内分别计价的类别。必须检查两者之和不大于已知输入总量，非负整数与 checked 运算不能省略。不能先按普通输入收费再追加完整写入费用。缺失写入量与真实零不同；有独立写入价格但缺必要数量 / 条件时不猜测金额。仅在经确认的来源格式明确不报告独立写入、且适用规则确实不区分写入时，才按其原有语义估算。

金额继续使用每百万费率的 `10^9` 整数原子与 `10^-15` 币种费用原子，checked i128；聚合后统一舍入，币种分开，不改变 Token 账本。

## 4. 扩展范围及更新方式

搜索调用、云端容器、文件存储等独立工具费用，以及图片、音频、实时语音和微调的专门用量 / 费用核算均未实现。这些需要独立的计量单位、身份、周期或媒体类型证据及专用规则，不能从文本 Token 推算，也不能把工具已包含的模型 Token 重复加计。它们单列为扩展计划，不自动扩大本次已经确认的本地文本工具交付范围。

生产应用使用随程序打包的离线目录；`scripts/update-offline-prices.mjs` 是开发者只读官方文档、审查差异后提交新目录的工具，不是运行时自动联网更新。运行时官方价格自动更新尚未实现，后续若纳入范围需验证来源、不可变历史版本和原子发布，失败保留旧目录；核实时间不能冒充历史价格生效日。

## 6. 缓存写入数量链路（M09h1a）

新增 nullable `UsageVector.cache_write_input`；适配器读取 rollout 的 `cache_write_input_tokens`，并明确定义用量对象内 `cache_write_tokens` 为本工具的兼容拼写，不冒充官方 rollout 字段。双字段值不同（含 null 与已知值冲突）拒绝，其他未知字段继续拒绝；字符串、布尔、小数和超 i64 范围不接受。缺失 / null 保持未知，真实 0 保持零。负数、命中 + 写入 > 输入及报告总量下界冲突由领域校验隔离。

累计差值包含写入计数；字段覆盖改变或无证明的下降不推进基线，明确阶段重置按新阶段核算。镜像 / 分叉的完整必要签名包含已知写入值；未知写入省略序列化，旧必要 JSON / 签名字节不变，不触发旧格式全历史自动重解析。写入不另加到输入 + 输出总量中。

schema v11 为 usage_events 增加 nullable 精确 INTEGER 字段与非负 / 包含关系约束；事件、必要观察、基线和检查点仍共用原事务，旧行保持 null。候选验证 / 切换及实际旧读取快照保留该分项。原始与核算 DTO 输出精确字符串，TokenTotals 独立返回值 / 覆盖 / 完整性；rollup cache version 升至 2，不读取旧五分项缓存。总览、会话详情和明细证据新增包含项；原 noncached_input 仍为输入 - 命中（包括写入），显示名改为“非缓存命中输入”，不能误称为四费率公式中的普通输入。

M09h1a 阶段没有第四种价格费率，已知正数写入返回 insufficient_usage，保留 Token；已知零兼容原三费率结果。M09h2 接四费率及正确扣除算法，M09h3 / h4 接可靠请求长度 / 实际模式后才能完成条件模型计价。数量接入不代表官方所有条件可采集。正式安装 / 发布的 0.1.2 尚不包含本增量；此前被旧适配器拒绝的历史记录不会自动重读，受控手动补读与实际日志兼容继续收尾，不恢复已取消的全历史自动重解析范围。

## 7. 四费率估算（M09h2）

当前源码 PriceRule / PriceRuleDraft 追加 nullable cache_write_rate_atoms，率值依然精确非负十进制整数，最大 10^15 原子；schema v12 持久化并保留旧行 null。版本化创建 / 替换 / 退休、别名、来源优先级及估价时点复用已验证的原匹配流程。对有完整必要数量和费率的消费，实际使用第 2 节四项公式，写入从普通输入扣除，不另加到总量或输出 / 推理收费中。条件目录仍只生成原 37 条 Standard / All / 无独立写入费率参考规则；本模块不把有分档 / 模式条件的官方价格扁平化。

证据边界明确如下：已知正数命中 / 写入必须有对应费率，缺失返回 insufficient_usage；已知零不要求该分项费率。某分项数量未知而其独立费率不同于普通输入时，若仍有输入可归于该未知分项，金额不确定，保持未计价。只有普通输入价与该分项价相同、或者其他已知包含项已经用完全部输入时，未知分项不会改变金额，可精确算出估算；数量仍为 null。旧三费率规则（写入价 null）对没有报告写入的旧用量保留原有参考估算语义，不声称未知写入为零或真实请求使用了 Standard；一旦报告正数写入且没有独立费率，仍不计价。未知量不在保存、DTO 或聚合中被填成零。

费用缓存版本升到 2，集合 ID / 指纹 / 读取过滤都包含新版本；旧 ready v1 集合被排除，查询同价格版本即时补算，后台补建新集合。价格更新只改变费用估算，旧实际读取快照和历史修订保留原结果，Token / 检查点不变。编辑器可保存独立写入费率、真实零或空未知；规则表显示四费率并注明包含关系，共享主题 / 隐私 / 历史流程保持。

自动验证包括 729 组普通 / 命中 / 写入类别独立预期、未知 / 零 / 正数、等价费率 / 零剩余输入、超 JS 精度整数、费率上界、v11→v12 旧 null、实际并发旧快照 / 价格历史 / 重开 / 旧缓存排除与补建。core / store 415 项通过，1 既有性能夹具 ignored；前端 37 单元及 11 浏览器检查通过。隔离 Win10 实际 WebView / SQLite / IPC 验证四项 1300 原子、UI 替换写入价为零后自动补建 700 原子、历史费率及消费 / 检查点保持；合成数据不表示真实账户账单。正式 0.1.2 安装 / 发布包尚无 M09h1a / M09h2，实际历史补读、单请求上下文、响应模式和地区证据继续按 M09h1 / h3–h5 推进。

## 8. 单响应输入证据的采集（M09h3a）

2026-10-03 核实官方 Codex 固定源码 `b741e480e203f037ca726bc2a76d99a8e8668e66`，不是只凭字段名判断语义。`TokenUsageInfo.fill_to_context_window` 会制造填满窗口的 last / total，普通 token_count 不能无条件证明真实请求输入；新 `token_usage_record` 的 usage 来自一次完成响应，并携带 response_id、线程 / 回合与线程累计。RawResponseCompleted 是实时事件，官方 rollout 策略不保存它；TokenUsageRecord 没有实际服务模式字段。turn_context / ThreadSettingsSnapshot 中的 service_tier 是设置，不能当作响应确认模式。

适配器已接 token_usage_record 的明确布局，只提取必要响应 ID、回合 ID、用量、线程累计和物理位置，不保存原始 metadata / 正文 / 运行时会话 ID。线程 ID 必须匹配已知来源会话、回合必须匹配有效元数据，身份长度 / 控制字符、整数 / 包含关系及完整响应输入输出均校验。该记录仅作为辅助证据，不另造消费事件。pending 证据随原 ReaderContext 检查点原子保存，可跨批次 / 重启；Box 只控制 Rust 内存布局，不改变必要 JSON 形状。

随后 token_count 在同文件代次、前后物理位置、回合和完整 last / cumulative 向量都匹配时，必要观察保存 request_usage 及其中的响应 ID，供后续计价关联；不将稀疏辅助字段映射到既有核算 request_identity，防止改变旧镜像 / 继承前缀。任意中间非空记录、无效行、元数据变化、向量 / 覆盖不同或重复使用都不能沿用该证据；失败仅缺请求证据，原 Token 核算照常。采集器规范化会话别名不等于来源线程 ID 改变，关联核对 provider_session_id，不假定内部会话键一定是 codex:<id>。旧无证据字段省略序列化，旧格式字节保持，已跨过的历史不自动重解析。

## 9. 被旧适配器拒绝的历史与明确重读（M09h1c）

旧解析器拒绝写入字段后，原物理检查点可能已越过该记录；仅重估费用或重放数据库里的必要观察都不能恢复未保存的用量。现在后端支持明确手动来源重读，选择已登记的启用本地文件，从零只读解析至作业所有的隔离候选，再复用完整核算 / 依赖 / 物理验证与账本验证后发布；不能通过删除检查点、清空事件或修改源文件实现补读。

普通重建行为保留，暂停来源不打开文件而重放已有历史。重读过程有分批进度、取消，文件缺失 / 未完整尾行 / 证据过期等失败保留旧结果，后台正常增量等待本作业释放。自动升级不触发全历史重解析。合成旧拒绝状态用正常 Writer 把检查点提交到源末尾而不保存用量，普通重建仍为 0，明确重读恢复 135 Token / 写入 22，重复重读及 SQLite 重开不重复，原 readonly 字节保持。

本阶段是后端能力与自动真实文件 IO 验证；诊断页操作 / main-only IPC 和正式包验收仍需接入，不把它写成已安装能力。恢复数量也不补造实际请求模式、长度或地区条件；条件模型完整计价继续 h3b–h5。

M09h1d 后续接入：诊断页现在提供“重读已启用来源”，与原“重建全部账本”分别说明并调用 main-only 命令。共用基本作业进度和安全取消，回复丢失保留该操作的 request_key，不能误用另一种重建模式重试。5 项浏览器检查与实际 Win10 隔离 WebView / SQLite / 任务服务通过；新代次替换且 Token / 只读源字节保持，mini 被拒绝，幂等重试返回原作业。当前源码普通使用入口已通，正式安装 / 真实历史格式验收仍须随下个候选完成，不自动触发历史重读。

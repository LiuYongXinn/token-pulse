# 开发实施与验收计划

设计总入口：[TokenPulse 详细开发设计](../design/development-design.md)。需求依据：[完整方案](../design/token-pulse-design.md)及 F13 账户额度 / F14 任务栏增补。本文定义从设计到生产实现的开发依赖、每步产物和完成标准，不表示工程已经创建或验证。

## 1. 开发环境与构建约定

- Windows 主开发环境安装 Rust stable 的 MSVC 工具链、Visual Studio C++ 构建工具与 Windows SDK、Node LTS，以及可用 WebView2。具体系统前置条件按 Tauri 官方说明核对。[Tauri Prerequisites](https://v2.tauri.app/start/prerequisites/)
- 工程初始化采用 Tauri 2、React / TypeScript / Vite、Cargo workspace；不将原型单文件直接改为生产业务入口。
- Rust / Node 的选定版本、目标架构、依赖锁文件与格式兼容清单写入项目实际开发说明。UI 用 npm 管理并提交 package-lock.json；发布不依赖 Node。
- 开发应用使用独立 application identifier / 数据目录、日志和单实例锁，防止测试迁移修改生产统计。
- 引入依赖与系统功能时检查许可证与最小权限；任务栏宿主按目标架构打包并测试。
- 本文命令是工程建立后应提供的约定。当前仓库只有设计与原型，不可宣称现在运行这些命令即可启动正式程序。

```powershell
# 建立工程并生成锁文件后
npm ci
npm run dev
npm run typecheck
npm run test
npm run test:e2e
npm run build
npm run tauri dev
npm run tauri build
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

package scripts 与 Cargo workspace 需要在 M01 实际建立；原生系统测试不由 browser e2e 取代。

## 2. 开发顺序与逐模块交付

|步骤|模块及依赖|必交付产物|通过后继续|
|---|---|---|---|
|M01|工程 / 运行壳|Tauri、React、workspace、窗口 / 托盘骨架、开发数据目录、锁文件、CI|冷启动、关闭隐藏、明确退出、开发数据隔离|
|M02|领域与契约|标准观察、Token 向量、状态 / 错误、DTO schema、类型生成、fixture manifest|Rust / TS 协议一致，未知值与大整数往返|
|M03|存储基础|v1 migration、单写线程、只读池、版本与事务、诊断 / jobs 基础表|外键与唯一约束、回滚、磁盘失败、不污染源目录|
|M04|Reader + CodexAdapter|字节读取、上下文、格式兼容、文件身份 / 锚点、必要观察|半行、UTF-8、损坏、超限行、模型 / cwd 更新|
|M05|AccountingEngine|流 / episode、增量、重复、分叉分类、独立预期夹具|分块一致、相同时间不同调用、交错流、不确定隔离|
|M06|采集调度|发现、watcher、防抖、核对、有界队列、来源能力、事务集成|后台采集、实时优先、漏事件补扫、重启 / 唤醒|
|M07|作业与重建|持久 JobManager、候选 ledger、验证 / 发布、依赖闭包、审计|取消边界、失败保留旧账本、旧新快照不混合|
|M08|查询服务|bundle、模型 / 项目汇总、上下文、真实快照租约、游标 / 覆盖|镜像不翻倍、时区 / DST、并发分页、NULL 分解|
|M09|计价服务|不可变价格版本、离线 / 自定义规则、精确金额、覆盖、重估|公式独立验证、未知规则、冲突、Token 不因重估改变|
|M10|主窗口七页面|按 UI 实施导航、筛选、图表、表格、详情、诊断、五页设置|页面与真实 DTO 连接，错误 / 空态、隐私、无障碍|
|M11|悬浮窗 / MiniController|两尺寸、费用 / 额度区域、固定范围、置顶、拖动、恢复交互|独立主筛选、范围联动、断屏、快捷键冲突|
|M12|账户适配器|受控 App Server 连接、能力 / 授权、epoch、额度 / 通知 / 退避|实际支持版本登录与额度，未知 / 过期 / 切换正确|
|M13|Windows 任务栏|先原生宿主可行性样机，再完整绘制 / IPC / 设置 / 回退|Windows 10 实际安全嵌入；Explorer / DPI / 拥挤恢复|
|M14|导出与数据维护|固定快照导出、一致备份、验证恢复、受控清除|精确字段、公式注入、跨设备离线恢复、源日志未改变|
|M15|系统集成|单实例、启动项、可选 notify、休眠、隐私宿主失联处理|普通用户行为、配置冲突 / 撤销、安全退出|
|M16|安装 / 更新 / 发布|安装器、宿主打包、WebView2、迁移、签名更新、卸载 / 第三方声明|隔离机器完整安装 / 更新 / 恢复 / 卸载验收|

M01 先提供最低托盘 / 生命周期保证，M15 完整验证这些能力；M03 的 jobs 基础不代替 M07 的业务状态机。主窗口每页、价格规则、小窗、账户和任务栏分别作为可评审模块提交，不等到 M16 一次提交。

M12 与 M13 在 M02 确立接口后可提前做能力样机，尽早发现版本 / 授权 / Explorer 限制；样机不得以模拟数据宣称正式接入完成。任务栏不支持的系统有明确回退，不取消其他功能交付。

复杂实现前先添加合成 / 脱敏夹具和独立预期；核心统计不得通过观看页面数字猜测正确性。每个小功能完成一次 Git 提交，标题和说明描述触发条件、结果及验证。

## 3. 自动验证层次

|层|执行内容|目的|
|---|---|---|
|静态 / 类型|Rust fmt / clippy、TS strict、DTO schema 生成差异|避免协议漂移与基础缺陷|
|纯算法|向量、episode、流、镜像 / 继承、精确金额、时区边界|可重放且独立可复核|
|存储集成|真实 SQLite、外键、单事务、版本切换、NULL、来源 EXISTS|防重算叠加与检查点分离|
|文件系统集成|临时只读来源、真实追加 / 替换 / 移动、watcher 故障|验证源只读、补漏和代次|
|IPC / 并发|越权、非法参数、乱序、游标过期、写入中分页|真实一致性，不只 revision 字符串相同|
|浏览器 UI|真实或明确 mock DTO 的页面、过滤、详情、隐私、空态|视觉和用户交互|
|原生 Windows|Tauri 窗口、托盘、任务栏、快捷键、DPI、生命周期|浏览器无法提供的能力|
|部署 / 灾难|迁移、磁盘满、损坏库、签名失败、恢复 / 卸载|生产数据保护与可恢复性|

CI 核心测试不读取开发者真实 `.codex` 或认证。使用临时目录并固定时钟；实际账户验收在明确授权的测试账户中进行，不把凭据写入 fixtures、日志或 CI secrets 之外的产物。

## 4. 故障注入与准确性门槛

至少在观察插入、事件插入、流更新、偏移更新、COMMIT 前后、通知发送和 ledger 切换各点注入进程终止 / 错误，验证重启后“全批有或全批无”。取消与 publishing 竞争、来源同时重写与追加要有自动场景。

独立 oracle 核对已明确单流账本，复杂夹具人工列出规范事件、继承和歧义。fixture 的预期不能由同一生产算法自动生成。记录比较事件身份集合与向量，不只看最终 total 正好相同。

性能数据集至少包含 30 万事件查询、1 GiB 日志与 1 万文件导入、多来源镜像与长会话；报告冷 / 热查询、P50 / P95 / 最大、峰值内存、CPU、WAL 与队列长度。WSL / 网络路径单独给结果。

指标目标来自[总设计第 9 节](../design/development-design.md#9-性能与可观察性)。未达标必须记录测量结果和调整，而不是把目标写成测试通过。

## 5. 原生兼容矩阵

|环境|验收重点|
|---|---|
|Windows 10 22H2 / 19045|首个任务栏适配器、普通用户、应用图标 / 时钟不重叠|
|Windows 11 实际测试版本|核心应用与任务栏分别记录；内部结构不支持则明确回退|
|100% / 125% / 150% / 200% DPI|字体与数字测量、跨屏拖动、任务栏位置|
|双屏 / 主屏改变 / 拔屏|小窗夹紧工作区，宿主重定位或回退，无孤立窗口|
|自动隐藏 / 小按钮 / 竖向|跟随系统；未适配形态不强行嵌入|
|Explorer 重启 / 宿主崩溃|托盘恢复、旧 HWND 失效、有限重试、布局安全恢复|
|高对比度 / 字体放大 / 主题|状态有文字，可读、焦点可见，无内容裁切|
|锁屏 / 休眠 / 无网络|日志补扫、额度旧快照、独立宿主恢复|

macOS 核心与平台适配保留于完整需求，Windows 任务栏功能不跨平台伪装；macOS 发布前分别验证其托盘、登录启动、权限、窗口和安装流程。

## 6. 交付完成定义

原 A01–A16 是最低全功能标准，另外补充：

|编号|新增验收|
|---|---|
|A17 账户来源|通过用户授权连接实际额度；本地统计无需账户服务即可运行|
|A18 额度正确性|实际周期、桶隔离、null / 0%、重置待更新、旧快照与切换 epoch 正确|
|A19 任务栏安全|在已声明支持版本实际嵌入、精简、恢复、脱离；不覆盖系统控件|
|A20 三入口一致|同 mini_scope 用量 / 费用一致，账户范围独立，隐私覆盖原生 IPC 与详情|
|A21 快照契约|并发写入下 bundle / 分页 / 导出仍一致；租约到期明确刷新|
|A22 数据来源审计|镜像、分叉、修订与重建可定位原始证据；不可确定数据单独表达|

发布产物包含源码、锁文件、迁移、协议 schema、固定夹具、测试报告、性能 / 兼容报告、安装包和第三方声明。演示原型、模拟额度或能显示窗口都不能替代这些交付。

完整设计里的外部源码只用于参考机制，本项目必须独立运行；不能把 `E:/Documents/Code/jetbrains-cc-gui`、`.tokentracker` 或本次对话工具当生产依赖。发布报告明确支持的 Codex 格式 / App Server 版本与未确定记录比例。

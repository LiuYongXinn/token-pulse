# 账户额度共享显示与验证

M12g 将正式账户快照接入总览右栏及独立小窗，继续沿用 [账户额度设计](../design/account-quota.md) 的范围与缺失规则。设置页、总览和小窗共享周期 / 日期格式。检测本地程序的规则和证据见 [本地账户服务检测与验收](local-account-detection.md)。

## 已实现行为

总览保留原有左右布局，账户区显示当前选定桶、实际周期的剩余条、重置时间 / 倒计时、最近成功读取时间和刷新入口。没有本地来源或本地统计读取失败时，账户区仍可独立读取。主窗口日期、来源、固定会话和估价时点不进入账户读取请求。账户时间使用保存的显示时区，而非小窗带入的临时主统计范围时区。

紧凑小窗保留 280×220 DIP，按实际周期显示短周期 / 周剩余及周重置时间和倒计时。点击额度区展开至 360×380 DIP 并打开可滚动详情，包括所有窗口、桶名、显示时区、最近成功时间和受限刷新。详情支持关闭、Escape 和键盘焦点循环。

周期由 `duration_mins` 判断：10080 分钟为周；较短周期按实际长度显示，不能将 primary / secondary 或数组位置固定解释为短周期 / 周。仅周窗口时短周期保留缺失；多个同长候选不能随便取一个，紧凑读数保持缺失，详情保留各窗口。其他长度及未知长度仍在完整详情中显示，不求和或平均。

真实 `0%` 显示零及长度为零的剩余条，`null` 显示“— / 未提供”，低于或等于 20% 保留琥珀提示及文字。倒计时只更新显示，不改百分比；到达实际重置时间显示“等待额度更新”，后端已有服务按该重置时刻触发一次受限刷新，成功读到新快照后才更新读数。

## 快照、更新与隐私

共享 `useAccountQuota` 在订阅完成后读取完整 `get_account_quota` DTO。`account_quota_changed` 只用于失效并重查；十秒可见轮询读取已有内存快照，不以此频率强制网络查询。窗口恢复可见时重新读取，倒计时独立每分钟更新。网络轮询、单飞、限流与失败退避继续由原有后台 owner 管理。

读请求序号及组件生命周期阻止迟到结果覆盖新查询；同一连接修订不能倒退。账户 epoch 变化、断开或账户能力失效通知立即清除可见旧缓存，再查询权威快照。普通读取失败保留上次成功 DTO 并明确标注旧快照，不能将失败换成零余额。

开启隐私立即移除额度、桶名、日期、详情和提示缓存；未确认隐私策略时也不显示。晚到的未隐藏响应经运行时门禁及本地 epoch 拒绝。小窗只读额度 / 受限刷新，不取得选择或管理连接权限。

## M12h：独立进程冷启动（2026-10-03）

`pwsh -NoProfile -File scripts/native-account-startup.ps1` 依次启动四个完整 Tauri 应用进程，共用 UUID 标识的隔离开发数据库。仅 debug 构建接受该入口，参数只能是 UUID 和四种有限阶段，不能指定任意数据路径。自动账户初始化仍走正常 `quota_config::initialize`，验收代码不额外调用初始化或连接。

首进程通过真实 main WebView IPC 保存经过选择能力校验的合成程序 / Home 和自动连接设置，保存本身不启动服务；第二进程从 SQLite 冷启动，读取实际 5 小时桶 75% 及两个桶元数据，并通过正式 IPC 核对。保存关闭自动连接不改变当前连接；第三进程保持断开，无旧额度、成功时间或新子进程。随后保存开启设置并只改写合成程序；第四进程因 SHA 指纹改变显示 error / 有限错误码，额度与成功时间保持空，不启动改变后的程序。脚本逐轮核对拥有的服务 PID 已结束。

Win10 19045 上四阶段 `NATIVE_ACCOUNT_COLD_OK` 与 `NATIVE_ACCOUNT_COLD_SEQUENCE_OK`、退出 0；scene 参数自动检查 1 项、desktop strict Clippy 通过。WebView2 注销 1412 仍单独记录。这个场景使用合成账户，未读取真实认证或修改用户 Home，不代替真实账户冷启动、系统选择器及 Windows 11 验收。
